# Agent Org V1.2 — Reliable Autonomous Completion

## Purpose and user-visible outcome

Make clean-project OpenAI runs reliably complete implementation, verification, independent review, and Chief acceptance without manual intervention. Preserve strict evidence ownership while distinguishing reviewer-produced evidence from evidence observed from other roles. Keep interrupted work recoverable in an isolated run workspace.

## Scope

- Reproduce and repair reviewer provenance failures through typed produced/observed evidence and corrective review turns.
- Restore isolated linked worktrees for current-project execution; preserve direct-project behavior only as an explicit compatibility concern, not the V1.2 default.
- Improve resume/interruption diagnostics and add `diff`/`doctor` where compatible with the existing CLI.
- Add deterministic provenance, correction, workspace, and resume tests plus full V1 regression.

## Non-goals

No new provider, cross-provider verification, automatic merge/PR, arbitrary shell access, dirty-tree execution, dashboard, or deployment.

## Current state and root-cause hypothesis

V1.1 has strict `assertScoped` evidence validation, but reviewer payloads expose raw receipt IDs and the model can place tester IDs in the review's single `evidenceReceiptIds` field. The runtime then rejects the review after tool execution, terminating the run. Current project mode was simplified to direct writes; V1.2 will use a linked worktree again so interruptions do not dirty the user's checkout.

## Architecture decisions

- Keep `ExecutionReceipt` runtime-owned and immutable.
- Model review output will carry separate observed and produced receipt references; runtime overwrites/constructs authoritative provenance fields.
- Reviewer context will summarize external verification without making external IDs selectable as self-evidence, while retaining lineage through observed references.
- Provenance/schema failures trigger bounded reviewer corrective turns, never developer rework.
- Current-project `WorkspaceSource` prepares a clean linked worktree and persists its identity; resume reuses it.

## Security and invariants

Strict role/task/run/iteration/workspace provenance remains enforced. Reviewer/tester cannot write. Clean-tree preflight remains mandatory. No reset or destructive cleanup occurs on interruption. Credentials and raw provider output are not persisted.

## Milestones

1. Audit/reproduce current failure and capture invalid payload (in progress).

4. Restore isolated worktrees, interruption/resume lifecycle, and CLI `diff`/`doctor`.

## Retrospective

The review failure was caused by one broad model-facing receipt list being used for both self-produced and externally observed evidence. V1.2 now separates those fields, hides external receipt IDs from the reviewer-produced context section, and performs runtime semantic validation that turns provenance mistakes into bounded structured-output corrections. Strict domain validation remains unchanged. Current-project execution again uses a linked worktree, preserving the user's clean checkout across interruption and making resume workspace identity durable. Deterministic behavior is green; live completion and repeated interruption acceptance remain outstanding until a clean real project is available without mutating or stashing user work.
